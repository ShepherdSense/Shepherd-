# Link-Dropout Bench — disturbance_clf under node/link loss

*2026-10-23, for Shepherd v0.24.0. Tool: `tools/bench_link_dropout.py`
(masking: `apply_link_dropout_features` in `tools/train_disturbance_clf.py`).
Motivation: WiFi-JEPA (Kim et al., arXiv:2607.11064) — link-masking during
training beat random masking (97.1 vs 105.1 mm MPJPE); we bench the same
idea on the phone-side disturbance classifier so it degrades gracefully
under node loss.*

> **Caveat — read first.** Every number below is **synthetic holdout /
> synthetic bench accuracy**. The training corpus and the bench set are
> both generated by parameterized disturbance models; **synthetic
> accuracy does NOT establish field accuracy.** No real-data validation
> loop for this classifier exists yet (BRIEF item 9). These numbers
> compare model variants against each other on shared synthetic ground —
> nothing more.

## Methodology

- **Bench set:** 4,000 synthetic events (1,000 per class) from the
  v0.24.0 trajectory-diverse generators, **seed 999** (neither model was
  trained on it), at a **fixed mesh size of 15 links** — a full 6-node
  mesh, the largest reference geometry in `docs/mesh_mode_spec.md`.
- **Models compared:**
  - **OLD** — the pre-v0.24.0 shipped `disturbance_clf.json` (saved
    before any changes), evaluated via a numpy forward pass replicating
    the Dart `TinyMlp` kernel (standardize → relu → relu → softmax).
  - **NEW** — the v0.24.0 retrained model (trajectory-diverse corpus +
    link-dropout augmentation, shipped as
    `assets/models/disturbance_clf.json`).
  - **NEW (no aug)** — ablation: same new corpus and split, trained
    *without* the dropout augmentation. Not shipped.
- **Masking:** for each drop count *k*, every bench example's raw
  feature vector is passed through `apply_link_dropout_features(x, k)`
  before inference. *k* runs 0 → 14 (14 = every non-primary link of the
  15-link mesh lost; the maximum sensible value).

## Runtime assumption for link masking (explicit)

The 10-feature input has **no per-link vector**, so a missing link
cannot be represented directly. Reading `AppState._classifyEvent`
(`lib/state/app_state.dart`):

- The classifier is only ever invoked for an event on a **surviving
  (primary) link**; a dropped primary link produces no event at all.
- Other links enter the feature vector only through three aggregate
  channels: `log_simul_links` (links disturbed within the last 5 s),
  `cross_driver` (>1 driver among those), and `log_mesh_links`.

Masking therefore operates **at feature level, exactly the way the
runtime would see it**: dropped links are assumed non-primary;
`simul_links` and `mesh_links` shrink by the drop count (floored so the
primary link remains), and `cross_driver` clears when fewer than 2
simultaneous links survive. The primary link's dip-derived features are
**not** touched — a dropped non-primary link never contributed samples
to the primary link's series.

One nuance, stated for honesty: mid-session, AppState's `history` map
retains keys for links seen earlier in the session, so the runtime
`log_mesh_links` can lag reality until a session restart. The bench's
mesh-count reduction is the **conservative (post-restart) value**; the
true mid-session effect on that one feature is smaller than benched.

## Reading the results

- **Trajectory diversity is the big effect, not dropout.** On the shared
  bench set the OLD model scores 0.868 at *k* = 0 — its PASSING and
  LINGERING classes collapse (0.767 / 0.748) on the randomized speeds,
  headings, start points and loiter behaviours it never saw in training.
  That is the WiFi-JEPA failure shape (narrow/fixed trajectories) showing
  up in our own corpus. NEW scores 0.961 on the same set.
- **Dropout degradation is small and flat — by construction.** Only 3
  of the 10 features carry any link-count information, and the
  simultaneous-link count in the corpus saturates at its floor of 1
  within a few drops. There is no per-link information in the input to
  lose, so there is little to degrade. "Graceful degradation" here is
  mostly a property of the aggregate feature design, and this bench is
  the evidence for it.
- **The augmentation earns its place, modestly.** NEW-with-augmentation
  loses 0.5 points from *k* = 0 → 14 vs 1.0 points without, and sits
  +0.2–0.4 points above the no-augmentation ablation at every *k* ≥ 2,
  at a −0.15 point cost at *k* = 0. Small, consistent, and in the
  intended direction — the augmented model is the one shipped.
- **FAULT never degrades** (1.000 / 0.997 at every *k*): its signature
  is a single pinned link, already at `simul_links` = 1 in training.
- **INTERFERENCE is NEW's weakest class** (0.905–0.915 across the
  bench): the widened interference patterns (bursts/chirp families) now
  overlap the gait-wobbled, dropout-pocked mover patterns. Reported,
  not tuned away — see the per-class holdout above (0.922).

## Reproduce

```sh
~/workspace/.mlvenv/bin/python tools/train_disturbance_clf.py   # seed 7
~/workspace/.mlvenv/bin/python tools/bench_link_dropout.py \
    --old /tmp/shepherd_old_clf/disturbance_clf.json.orig

# Ablation column (NEW without link-dropout augmentation):
~/workspace/.mlvenv/bin/python tools/train_disturbance_clf.py \
    --no-aug --out /tmp/disturbance_clf_noaug.json
~/workspace/.mlvenv/bin/python tools/bench_link_dropout.py \
    --old /tmp/shepherd_old_clf/disturbance_clf.json.orig \
    --new /tmp/disturbance_clf_noaug.json
```
